## 1. การตัดสินใจที่ตกลงแล้ว

1. **spec เดียวครอบภาพรวม แบ่งลงมือ 6 รอบ** แต่ละรอบมีแผนของตัวเอง (แนวเดียวกับป่าไม้ 1a/1b/1c)
2. **หนังสืออยู่กับ "ตำแหน่ง/หน่วยงาน" ไม่ใช่ "คน"** — สารบรรณมีสมุดผู้รับของตัวเอง แล้วผูกคนจาก
   ทะเบียนผู้ใช้เข้าตำแหน่ง คนย้ายหรือลาออกหนังสือไม่หาย และรักษาราชการแทนได้โดยผูกหลายคน
3. **แยกที่ `/saraban` ธีมน้ำเงินตาม handoff** — ไม่ใช้ `AdminLayout` เพราะสารบรรณมีเมนู 8 รายการ
   กับสวิตช์โหมดของตัวเอง (ซ้อนในหลังบ้านจะได้ sidebar สองชั้น) และโหมดเจ้าหน้าที่เป็นจอมือถือ
   720px ที่ไม่มี sidebar เลย แต่ใช้ auth / สิทธิ์ / store / zod ชุดเดียวกับพอร์ทัล
4. **โหมดเต็ม = สิทธิ์ `saraban` · โหมดเจ้าหน้าที่ = ถูกผูกเข้าตำแหน่ง** — การผูกตำแหน่งคือสิทธิ์เอง
   ไม่มีสองที่ให้ดูแลแล้วเพี้ยนกัน (ติ๊กสิทธิ์แต่ลืมผูก = จอว่าง · ผูกแต่ลืมติ๊ก = หนังสือกองค้างที่คน
   ที่เปิดดูไม่ได้)
5. **ไม่รับหนังสือชั้นลับ/ลับมาก** — โหมดเต็มเห็นหนังสือทุกเรื่อง ป้าย "ลับ" ที่ไม่กันใครเลยทำให้คน
   เข้าใจผิดว่าปลอดภัย ดีกว่านั้นคือไม่รับเข้าระบบเลยจนกว่าจะมีรอบที่ออกแบบการเข้าถึงของตัวเอง
6. **เลขทะเบียนเริ่ม 1 ใหม่ทุก 1 ต.ค. (ปีงบประมาณ)** ตาม handoff และที่เทศบาลใช้
   — หมายเหตุ: ระเบียบสำนักนายกรัฐมนตรีว่าด้วยงานสารบรรณ พ.ศ. 2526 ข้อ 38.1/40.1 เขียนว่า
   "จนสิ้นปีปฏิทิน" นี่จึงเป็นทางเลือกของเทศบาล ขอบปีอยู่ในฟังก์ชันเดียว (`fiscalYearOf`) เปลี่ยนที่เดียว
7. **ออกเลขด้วย max+1 ชน unique index แล้วลองใหม่** — ไม่ใช้ตัวนับ `$inc` (ดูข้อ 4)
8. **หนังสือส่งระบบประกอบ "ที่" ให้ และหนังสือเวียนมีชุดเลขของตัวเอง** → ทะเบียนสามชุด
   `in` / `out` / `circular`

## 3. โมเดลข้อมูล

```ts
type SarabanRegister = 'in' | 'out' | 'circular';
type SarabanLevel = 'normal' | 'urgent' | 'very-urgent' | 'most-urgent';
type SarabanStatus = 'pending' | 'in-progress' | 'done' | 'void';
type SendMethod = 'system' | 'post' | 'hand';

type SarabanDoc = {
  id: string;                 // uuid — client สร้างมาเป็น idempotency key (ข้อ 4)
  register: SarabanRegister;
  fiscalYear: number;         // ปีงบ พ.ศ. เช่น 2570
  no: number;                 // เลขทะเบียน 1..n ต่อ (register, fiscalYear)
  ref: string;                // ที่หนังสือ — รับ: พิมพ์เอง · ส่ง/เวียน: ระบบประกอบ
  docDate: string;            // ลงวันที่ 'YYYY-MM-DD'
  party: string;              // รับ: จาก · ส่ง/เวียน: ถึง
  subject: string;
  level: SarabanLevel;
  dueDate: string;            // '' = ไม่กำหนด (ส่ง/เวียนเป็น '' เสมอ)
  holderUnitId: string;       // รับ: หนังสืออยู่กับตำแหน่งไหน · ส่ง/เวียน: ส่วนราชการเจ้าของเรื่อง
  status: SarabanStatus;
  sendMethod: SendMethod | '';  // '' จนกว่าจะบันทึกว่าส่งแล้ว
  voidReason: string;         // '' ถ้าไม่ได้ยกเลิก
  files: SarabanFile[];
  events: SarabanEvent[];     // ประวัติ ฝังในหนังสือ
  registeredAt: string;       // ISO
  registeredBy: string;       // clerkId
  updatedAt: string;
};

type SarabanFile = {
  id: string;                 // uuid — ใช้ใน URL แทน key ที่มี '/'
  key: string;                // object key ใน bucket: 'saraban/<uuid>.<ext>'
  name: string;               // ชื่อไฟล์เดิม
  format: 'pdf' | 'jpg' | 'png';  // จากเนื้อไฟล์ (magic bytes) ไม่ใช่จากนามสกุล
  bytes: number;              // จาก HeadObject ไม่ใช่จาก client
  pages: number;              // เซิร์ฟเวอร์นับตอนอัป · รูปภาพ = 1 · 0 = อ่าน PDF ไม่ได้
  uploadedAt: string;
  uploadedBy: string;
};

type SarabanEvent = {
  id: string;
  at: string;                 // ISO
  by: string;                 // clerkId (dev-open = 'dev-open')
  byName: string;             // ชื่อ ณ เวลาที่ทำ
  kind: 'received' | 'issued' | 'edited' | 'file-added' | 'file-removed' | 'sent' | 'voided';
  note: string;
  changes?: { field: string; from: string; to: string }[];   // เฉพาะ edited
};

type SarabanUnit = {
  id: string;                 // seed: slug อ่านง่าย · สร้างจากหน้าเว็บ: uuid
  name: string;               // 'ปลัดเทศบาล' · 'กองช่าง'
  dept: string;               // สังกัด
  refCode: string;            // 'ชม 55201' — '' = ออกหนังสือส่งไม่ได้
  order: number;
  isActive: boolean;          // ปิดแทนการลบ — หนังสืออ้าง id อยู่
  memberClerkIds: string[];   // รอบ 3
};

type SarabanYear = {          // _id = `${register}-${fiscalYear}`
  register: SarabanRegister;
  fiscalYear: number;
  startNo: number;
  setAt: string;
  setBy: string;
};
```

คีย์เป็นภาษาอังกฤษ ป้ายบนจอเป็นภาษาไทย แนวเดียวกับ `JobStatus`

### ป้ายสถานะแยกตามทะเบียน

| `status` | รับ | ส่ง / เวียน | สี (bg / fg) |
|---|---|---|---|
| `pending` | รอเกษียน | — | `#FDF3E1` / `#8A5A00` |
| `in-progress` | ดำเนินการ | **รอส่ง** | `#E8EFF8` / `#1E4D8C` |
| `done` | เสร็จสิ้น | **ส่งแล้ว** | `#E6F4EE` / `#1C7C54` |
| `void` | ยกเลิก | ยกเลิก | `#F1F5FA` / `#66758A` + ขีดฆ่าทั้งแถว |
| (คำนวณ) | เกินกำหนด | — | `#FDECEA` / `#B3261E` |

**ส่ง/เวียนใช้ "รอส่ง/ส่งแล้ว" ไม่ใช่ "ดำเนินการ/เสร็จสิ้น" แบบในต้นแบบ** — จงใจเบี่ยงจากแบบ เพราะ
ต้นแบบไม่เคยนิยามว่าสองคำนั้นหมายถึงอะไรสำหรับหนังสือส่ง พอวงจรชีวิตคือ "ออกเลข → ส่ง" ป้ายควร
บอกตรง ๆ สียังตามแบบ

"รอลงรับ" ในต้นแบบไม่ใช้ — ยังไม่มีหนังสือเข้ามาทางอิเล็กทรอนิกส์จากหน่วยงานภายนอก

### สิ่งที่คำนวณได้ ไม่เก็บ

- **เกินกำหนด** = `register === 'in'` และ `dueDate !== ''` และ `dueDate < วันนี้ (กรุงเทพฯ)` และ
  `status` ไม่ใช่ `done`/`void` — ถ้าเก็บเป็นสถานะจริงต้องมี cron คอยเปลี่ยน วันที่ cron ไม่ทำงาน
  สถานะผิดเงียบ ๆ แสดงแทนป้ายสถานะจริงบนจอ
- **ไร้กระดาษ** = `files.length > 0` (นิยามของ handoff)
- **กฎกรองของทะเบียนอยู่ใน `matches()` ฟังก์ชันเดียว** Mongo query ต้อง "พูดกฎเดียวกัน" แยกกัน
  คนละที่ จึงเทสต์ `matches()` ไว้เป็นข้อสอบเทียบ — แนวเดียวกับ [`jobs-store.ts`](../../../src/lib/jobs-store.ts)

### ประวัติเก็บชื่อ ณ เวลาที่ทำ

`events[].byName` คือชื่อจากทะเบียนผู้ใช้ตอนกดบันทึก (ถ้าไม่มี → อีเมล → clerkId) ส่วน
`holderUnitId` อ้างด้วย id — เปลี่ยนชื่อตำแหน่งแล้วจอควรแสดงชื่อใหม่ แต่ audit trail ต้องไม่ถูกแก้
ย้อนหลัง

### ชั้นความลับ

ไม่มีฟิลด์ ใต้ฟอร์มลงรับมีข้อความหนึ่งบรรทัด "หนังสือชั้นลับขึ้นไปให้ดำเนินการนอกระบบตามระเบียบว่าด้วย
การรักษาความลับของทางราชการ" — ช่องที่เลือกได้ค่าเดียวเป็นแค่สิ่งรกตา

### ขนาดเอกสาร

หนังสือหนึ่งเรื่องมี event หลักสิบ ไฟล์ไม่เกิน 10 — ห่างเพดาน 16MB ของ Mongo document หลายหลัก
การฝังประวัติจึงไม่มีความเสี่ยงเรื่องโตไม่จำกัดแบบที่ทำให้ปฏิทินต้องแยก collection

### ปีงบคิดจากวันที่ลงรับ ไม่ใช่วันที่ในหนังสือ

```
fiscalYearOf('2026-09-30') → 2569
fiscalYearOf('2026-10-01') → 2570
```

รับวันที่ **ตามเวลากรุงเทพฯ** ด้วย `bangkokDateOf(now)` ใน `saraban-number.ts` — ลงรับตอน
00:30 วันที่ 1 ต.ค. คือ 17:30 UTC วันที่ 30 ก.ย. ถ้าคิดจาก UTC จะได้เลขของปีงบเก่า
(`bangkokDateOf` รับเวลาเข้ามาเพื่อให้ปีงบกับเวลาลงทะเบียนมาจากขณะเดียวกัน และคำนวณจาก UTC+7
คงที่ ไม่พึ่งรูปแบบ locale แบบ `todayInBangkok()` — ปีงบเป็นส่วนของ unique key)

หนังสือลงวันที่ 28 ก.ย. ที่มาถึงวันที่ 2 ต.ค. ได้เลขของปีงบใหม่ — เลขทะเบียนเป็นของ "วันที่ลงรับ"

### ออกเลข: max+1 ชน unique index

```
1  อ่าน max(no) ของ (register, fiscalYear) — รวมแถวที่ยกเลิกแล้ว (เลขไม่ถูกใช้ซ้ำ)
2  no = max + 1 · ถ้ายังไม่มีหนังสือในปีนั้น: no = startNo ?? 1
3  insert — unique index { register, fiscalYear, no }
4  ชน (E11000 บน index นี้) → กลับไปข้อ 1 · ครบ 5 ครั้ง → 503 number_busy
```

**ทำไมไม่ใช้ตัวนับ `$inc`:** ถ้า `$inc` สำเร็จแต่ insert ล้ม เลขนั้นหายไปหนึ่งเลข ทะเบียนมีรูที่ดู
เหมือนหนังสือถูกลบ และทั้ง repo ไม่มี transaction (`startSession` ไม่มีสักที่) แบบ max+1 ถ้า insert
ล้ม เลขนั้นยังไม่เคยถูกใช้ ครั้งหน้าได้เลขเดิม

**unique index คือสิ่งที่ทำให้เลขซ้ำเป็นไปไม่ได้** ไม่ใช่โค้ด — จึง **ห้ามกลืน error ของ
`createIndexes` แบบ `jobs-store`** ถ้าสร้าง index ไม่สำเร็จ การออกเลขต้องล้มดัง ๆ (500) ไม่ใช่ออกเลข
ต่อไปโดยไม่มีอะไรกันซ้ำ นี่คือจุดเดียวที่ store นี้ต่างจากแพทเทิร์นเดิมโดยตั้งใจ

แบ็กเอนด์ไฟล์ทำ max+1 แบบอ่าน-แก้-เขียน ไม่มี lock — ยอมรับได้ด้วยเหตุผลเดียวกับ `jobs-store`
(dev fallback คนเดียวใช้) และปฏิเสธตัวเองตอน production ที่ไม่มี `MONGODB_URI` ด้วย
`assertFileBackendAllowed()` แบบเดียวกัน

### idempotency — กดซ้ำไม่ได้เลขสองเลข

client สร้าง `id` (uuid) ครั้งเดียวต่อการเปิดฟอร์ม ส่งมากับ POST ถ้า `id` นั้นมีอยู่แล้ว (unique index
บน `id`) และ `registeredBy` เป็นคนเดียวกัน → คืนหนังสือเดิม 200 แทนที่จะออกเลขใหม่ · คนละคน →
`409 id_conflict` (uuid ชนกันเองไม่เกิดจริง ที่เหลือคือบั๊กหรือการยิงซ้ำโดยเจตนา)

ปิดปุ่มระหว่างส่งกันดับเบิลคลิกได้ แต่กันกรณี "insert สำเร็จแล้วเน็ตหลุดก่อนได้คำตอบ แล้วผู้ใช้กดใหม่"
ไม่ได้ — กรณีนั้นคือเลขผีหนึ่งเลขในทะเบียนราชการที่ต้องมีคนตามยกเลิก

### รูปแบบเลข

| | ในทะเบียน | ใน "ที่" |
|---|---|---|
| รับ | `0421` | พิมพ์เองตามหนังสือ |
| ส่ง | `0388` | `ชม 55201/388` |
| เวียน | `ว 0012` | `ชม 55201/ว 12` |

ในทะเบียนเติมศูนย์ 4 หลักตามแบบ (เกิน 9999 แสดงตามจริง) · ใน "ที่" ไม่เติมศูนย์ ตามรูปแบบหนังสือราชการ

`composeRef(refCode, register, no)` ประกอบที่เซิร์ฟเวอร์ตอน insert — **"ที่" ของหนังสือส่งแก้ไม่ได้**
ถ้าเลือกส่วนราชการผิด ให้ยกเลิกแล้วออกเลขใหม่ เพราะ "ที่" อาจถูกพิมพ์ลงหนังสือจริงไปแล้ว

### เลขเริ่มต้นกลางปี

เริ่มใช้ระบบกลางปีงบต้องออกเลขต่อจากทะเบียนกระดาษได้ → `sarabanYears.startNo`

**ตั้งได้เฉพาะเมื่อ (register, fiscalYear) นั้นยังไม่มีหนังสือเลย** — ตั้งทีหลังได้เท่ากับเปิดทางให้เลข
ซ้ำ (ตั้งต่ำกว่า max) หรือมีรู (ตั้งสูงกว่า max+1) ตอบ `409 year_in_use` · ผู้มีสิทธิ์ `saraban` ตั้งได้
(ธุรการคือคนที่รู้เลขล่าสุดของทะเบียนกระดาษ) · รับ 1–99999 · บันทึก `setAt`/`setBy` ไว้ในเอกสารปี
เพราะยังไม่มีหนังสือให้ฝาก event

ถ้าเริ่มใช้ตรง 1 ต.ค. 2569 (ต้นปีงบ 2570) ไม่ต้องใช้ส่วนนี้เลย

## 5. ไฟล์แนบ — Railway Storage Bucket

สารบรรณ **ไม่ใช้ Cloudinary** (เปลี่ยนเมื่อ 2026-10-30 ดูบันทึกท้ายเอกสาร) ไฟล์อยู่ใน Railway Storage
Bucket ซึ่งเป็น S3-compatible และ private เสมอ — ไม่มี URL สาธารณะ เปิดได้ผ่านลิงก์ชั่วคราวเท่านั้น
ซึ่งตรงกับธรรมชาติของหนังสือราชการ · แผนที่ ป่าไม้ และรูปหน้าเว็บยังใช้ Cloudinary ตามเดิม ไม่แตะ

- PDF/JPG/PNG · ไม่เกิน 10MB ต่อไฟล์ · ไม่เกิน 10 ไฟล์ต่อเรื่อง
- key ของทุกไฟล์ขึ้นต้นด้วย `saraban/` — bucket ใช้กับสารบรรณอย่างเดียวก็จริง แต่ prefix ทำให้
  `checkAttachment` ปฏิเสธ key ที่ไม่ได้มาจากเส้นทางของเราได้ และเผื่อวันที่ bucket ถูกใช้ร่วม
- **เซิร์ฟเวอร์ของเราเป็นผู้เดียวที่เขียนลง bucket** (เบราว์เซอร์ไม่ได้ลายเซ็นอัปตรง) — metadata ที่
  อยู่บน object จึงเชื่อได้ เป็นฐานของการตรวจทั้งหมดข้างล่าง

### อัปผ่านแอป ไม่อัปตรงจากเบราว์เซอร์

สเปกฉบับแรกให้เบราว์เซอร์อัปตรงเพื่อเลี่ยงเพดาน body/response ของ Vercel — พอร์ทัล deploy บน
Railway ซึ่งไม่มีเพดานนั้น การอัปผ่านแอปจึงคุ้มกว่า: เซิร์ฟเวอร์เห็นเนื้อไฟล์จริง ตรวจชนิดจากเนื้อไฟล์และ
นับหน้า PDF ได้ทันที ไม่ต้องตั้ง CORS และไม่ต้องดาวน์โหลดไฟล์กลับมาอ่านอีกรอบ · ผู้ใช้หลักสิบคน
ไฟล์ไม่เกิน 10MB ไม่เป็นภาระของแอป

`POST /api/admin/saraban/uploads` — หนึ่งไฟล์ต่อหนึ่งคำขอ body เป็นเนื้อไฟล์ดิบ (ไม่ใช่ form-data)

1. `bodyParser: false` แล้วอ่าน stream เองพร้อมนับไบต์ เกิน 10MB หยุดอ่านแล้วตอบ `413 file_too_large`
   — Railway ไม่มีตัวกั้นขนาดที่ขอบแบบ Vercel ถ้าไม่กันตรงนี้ก็ไม่มีใครกัน (หลักเดียวกับ LINE webhook)
2. `sniffFormat(bytes)` ดูชนิดจาก magic bytes (`%PDF-` · `FF D8 FF` · `89 50 4E 47`) — **ไม่เชื่อ
   นามสกุลหรือ Content-Type ที่เบราว์เซอร์ส่งมา** ไม่ตรงชนิดที่รับ → `400 bad_format`
3. นับหน้า: PDF ใช้ `pdf-lib` (เปิดไม่ได้ เช่นเข้ารหัสหรือไฟล์เสีย → `0` = ไม่รู้ ยังรับไฟล์) · รูปภาพ = 1
4. `PutObject` ที่ key `saraban/<uuid>.<ext>` ตั้ง `ContentType` ตามชนิดที่ sniff ได้ และ metadata
   `pages` → ตอบ `{ key }`

### บันทึกหนังสือ — เซิร์ฟเวอร์ไม่เชื่อข้อมูลไฟล์จาก client

ฟอร์มถือไฟล์ไว้ในเบราว์เซอร์ กด "ลงรับ" แล้วจึงอัปทีละไฟล์ จากนั้นส่ง `files: [{ key, name }]` มากับ
`POST /docs` เซิร์ฟเวอร์ `HeadObject` ทุก key แล้ว `checkAttachment()` ตรวจ:

1. key ขึ้นต้นด้วย `saraban/` และ object มีอยู่จริง
2. `ContentType` อยู่ใน pdf/jpeg/png · ขนาด ≤ 10MB
3. มี metadata `pages` — ไม่มี = object นี้ไม่ได้มาจาก `uploads.ts` → ปฏิเสธ
4. **key นี้ยังไม่ถูกแนบกับหนังสือเรื่องใด** (index บน `files.key`) — ไม่งั้นคนแนบ key เดียวกันซ้ำสองเรื่อง
   ได้ แล้ววันที่เรื่องหนึ่งลบไฟล์ อีกเรื่องเสียไฟล์ไปด้วย
5. `bytes` · `pages` · `format` ที่บันทึกมาจาก object ไม่ใช่จาก client

### บันทึกล้มแล้วลบ

ถ้าบันทึกไม่ผ่าน (validation, ออกเลขไม่ได้) เซิร์ฟเวอร์ลบไฟล์ที่ request นั้นอ้างถึงทันที — **เฉพาะ key
ใต้ `saraban/` ที่ยังไม่ผูกกับหนังสือเรื่องใด** ไม่งั้นคนส่ง key ของหนังสือคนอื่นมาใน request ที่ตั้งใจ
ให้ล้ม แล้วไฟล์ราชการถูกลบ · ความเสี่ยงที่เหลือ: ปิดแท็บหลังอัปก่อนบันทึก → ไฟล์กำพร้าใน bucket
(ยอมรับในรอบ 1 สคริปต์กวาดไฟล์กำพร้าทำพร้อมสคริปต์สำรองได้)

### เปิดดู

`GET /api/admin/saraban/docs/[id]/files/[fileId]` ตรวจสิทธิ์แล้ว redirect 302 ไปลิงก์ชั่วคราว
(presigned GET) อายุ 5 นาที ตั้ง `ResponseContentDisposition: inline; filename*=UTF-8''<ชื่อเดิม>` ให้
PDF เปิดในแท็บพร้อมชื่อไทยที่ถูกต้อง · เป็นการเปิดหน้าใหม่ ไม่ใช่ fetch จากสคริปต์ จึงไม่ต้องตั้ง CORS

### ลบไฟล์แนบ

ได้เฉพาะตอน `pending` / `in-progress` — `removeFile` ใน DB ก่อน แล้วค่อย `DeleteObject` + event
`file-removed` (เก็บชื่อไฟล์) ลบใน DB สำเร็จแต่ลบใน bucket พลาด = ไฟล์กำพร้าหนึ่งไฟล์ ซึ่งเสียหาย
น้อยกว่ากลับลำดับ **รอบ 4 ต้องห้ามลบไฟล์ที่มีตรา/ลายมือ/การลงนามอ้างอยู่**

### ไม่มี bucket

ตัวแปร `BUCKET_*` ไม่ครบ → ลงรับได้ตามปกติ ช่องแนบไฟล์แสดง "ยังไม่ได้ตั้งค่าที่เก็บไฟล์ — แนบไฟล์
ไม่ได้" (หลัก zero-config) API ไฟล์ตอบ `503 storage_not_configured`

### ตั้งค่า bucket (ครั้งเดียว ในหน้า Railway)

1. project → **Create → Bucket** · **region เดียวกับ service แอป** (เปลี่ยนทีหลังไม่ได้)
2. bucket แยกสำหรับทดสอบ (bucket ที่สอง หรือ environment `staging`) — ห้ามทดสอบบน bucket จริง
   เพราะไม่มี backup ลบผิดกู้ไม่ได้
3. service แอป → Variables → reference ค่าของ bucket: `BUCKET_NAME`←`BUCKET` ·
   `BUCKET_ENDPOINT`←`ENDPOINT` · `BUCKET_REGION`←`REGION` · `BUCKET_ACCESS_KEY_ID`←`ACCESS_KEY_ID` ·
   `BUCKET_SECRET_ACCESS_KEY`←`SECRET_ACCESS_KEY` (ไม่ใช้ preset "AWS SDK" ที่ตั้งชื่อเป็น `AWS_*`)
4. localhost: คัดลอกค่าจากแท็บ Credentials ของ **bucket ทดสอบ** ลง `.env.local`
5. ไม่ต้องตั้ง CORS ในรอบ 1 — รอบ 4 ต้องเปิด `GET` ให้โดเมนเว็บเพื่อ pdf.js

| ชั้นความเร็ว | ปกติ / ด่วน / ด่วนมาก / ด่วนที่สุด |
| เสนอถึง | จากสมุด (active) · ค่าเริ่มต้นปลัดเทศบาล |

**ช่องวันที่ทำเอง ไม่ใช้ `<input type="date">`** — ช่องของเบราว์เซอร์แสดงตามภาษาของเครื่อง บังคับเป็นปี พ.ศ.

2400 ปฏิเสธพร้อมบอก "ใส่ปีเป็น พ.ศ." ไม่เดาว่าเป็น ค.ศ. · ค่าที่ส่งเข้า API ยังเป็น ISO ค.ศ. และ zod ยังกันช่วงปี
ค.ศ. 1900–2100 ไว้อีกชั้น (เปลี่ยนเมื่อ 2026-10-31 ตามคำขอผู้ใช้ — `parseThaiInput` ใน `saraban-view.ts`)

## 10. สิ่งที่รู้แล้วของรอบ 2–6 (รายละเอียดตัดสินในแผนของแต่ละรอบ)

### รอบ 2 — เกษียนและติดตาม

- เดินสถานะด้วย state machine แยกไฟล์แบบ [`job-status.ts`](../../../src/lib/job-status.ts):
  `pending → in-progress` (เกษียนส่งต่อครั้งแรก) · `→ done` ("ส่งคืนสารบรรณ (จบเรื่อง)")
- event ใหม่: `annotated` (ข้อความ + ปลายทาง) · การส่งต่อเปลี่ยน `holderUnitId`
- **แจ้งเวียนภายใน** = รายการตำแหน่งที่ต้องรับทราบ แต่ละตำแหน่งกด "ทราบ" ของตัวเอง
- "+ เพิ่มผู้รับที่ยังไม่ลงทะเบียน" ของ handoff = **เพิ่มตำแหน่งในสมุด** (ชื่อ + สังกัด) ไม่มีรหัส
  `NP-xxxx` — พอร์ทัลไม่ใช่เจ้าของทะเบียนผู้ใช้ และไม่สร้างผู้ใช้ในนั้นนอกเส้นทางสมัคร/อนุมัติ
- ปุ่ม "ลงนามดิจิทัล" ในหน้าเกษียนย้ายไปรอบ 4

### รอบ 3 — โหมดเจ้าหน้าที่

- งานของฉัน = หนังสือที่ `holderUnitId` อยู่ในตำแหน่งที่ฉันถูกผูก + แจ้งเวียนที่ยังไม่กดทราบ
- ผู้จัดการผูกคนจากทะเบียนผู้ใช้เข้าตำแหน่งที่ `/saraban/units`
- สวิตช์โหมดแสดงเมื่อผู้ใช้มีทั้งสิทธิ์ `saraban` และถูกผูกตำแหน่ง
- **ต้องตัดสินในรอบ 3:** "ลงรับหนังสือใหม่" ในโหมดเจ้าหน้าที่ออกเลขทะเบียนราชการได้ — เปิดให้ทุกคน
  ที่ถูกผูกตำแหน่ง หรือเฉพาะผู้มีสิทธิ์ `saraban`
- ปุ่ม "ถ่ายรูป / สแกนหนังสือ" = อัปรูปจากกล้องได้ **แต่ไม่มี OCR** (นอกขอบเขต)

### รอบ 4 — เอกสาร

- เรนเดอร์หน้า PDF ในเบราว์เซอร์ด้วย pdf.js จากลิงก์ชั่วคราว (ไม่มี Cloudinary ช่วยแล้ว) — ต้องตั้ง CORS
  ของ bucket ให้ `GET` จากโดเมนเว็บ · จำนวนหน้าที่รอบ 1 บันทึกไว้ใช้วางตรา/ลายมือรายหน้า
- ลายมือเก็บเป็นเส้นเวกเตอร์ต่อหน้า (ไม่ใช่ภาพ) · ตราเก็บ `{label, color, x%, y%, rot, page}`
- **การลงนามในรอบนี้คือบันทึก ผู้ลงนาม · เวลา · IP · sha256 ของไฟล์ ลงใน event** ป้ายต้องเขียนว่า
  **"ลงนามในระบบ"** ไม่ใช่ "ลงนามดิจิทัล · ตรวจสอบแล้ว" แบบในต้นแบบ — ยังไม่ได้ผูกใบรับรอง
  (Thai Digital ID / CA) คำว่า "ตรวจสอบแล้ว" บนระบบราชการทำให้คนเข้าใจผิดเรื่องน้ำหนักทางกฎหมาย
  (หลักเดียวกับ "ป้ายกำกับที่ต้องเขียนให้ตรง" ในสเปกป่าไม้ §5)
- ห้ามลบไฟล์แนบที่มีตรา/ลายมือ/การลงนามอ้างอยู่

## 12. ที่ยังค้าง

### รอยืนยันจากเทศบาล (ลง README ด้วย)

1. **ผังตำแหน่ง/หน่วยงานจริง และ `refCode` ของแต่ละกอง** — seed ใช้รายชื่อจากต้นแบบ และใส่
   `refCode` เฉพาะสำนักปลัด (`ชม 55201` ที่ปรากฏในต้นแบบสามครั้ง) กองอื่นเว้นว่างไว้ ไม่เดารหัส
   ส่วนราชการ แก้ได้ที่ `/saraban/units`
2. **หนังสือเวียนแยกชุดเลขตามที่เข้าใจหรือไม่** (ระเบียบงานสารบรรณ ข้อ 17)
3. **วันเริ่มใช้งานจริง** — 1 ต.ค. 2569 ไม่ต้องตั้งเลขเริ่มต้น · กลางปีต้องได้เลขล่าสุดของทะเบียนกระดาษ

### ต้องตรวจเป็นงานแรกของแผนรอบ 1B

1. **bucket ตั้งครบตามข้อ 5** (ตัวจริง + ตัวทดสอบ · region · ตัวแปร) แล้ว smoke บน bucket ทดสอบ:
   อัป → HeadObject เห็น `ContentType` และ metadata `pages` → ลิงก์ชั่วคราวเปิด PDF ในแท็บด้วยชื่อไทย
2. **ลิงก์ชั่วคราวหมดอายุจริง** — สร้างลิงก์อายุสั้นแล้วเปิดหลังหมดเวลา ต้องได้ 403
3. **ที่สำรองไฟล์ก่อนเปิดใช้จริง** — Railway Bucket ไม่มี backup อัตโนมัติและไม่มี versioning ทะเบียน
   ราชการที่ไฟล์หายกู้ไม่ได้ ต้องมีสคริปต์คัดลอกทั้ง bucket ไปปลายทางอื่นเป็นระยะ (ปลายทางให้เทศบาลเลือก)

### แยกจากสารบรรณ — แจ้งเป็นงานของแผนที่/ป่าไม้

ไฟล์เต็มของแผนที่/ป่าไม้เปิดผ่าน `signedRawUrl()` ของ Cloudinary ที่ส่ง `expires_at` ให้ `cloudinary.url()`
ยังไม่เคยยืนยันว่า Cloudinary บังคับเวลาหมดอายุบน delivery URL จริง (บางกรณีต้องใช้ token-based auth
หรือ `private_download_url`) ถ้าไม่หมดอายุ ลิงก์ที่ถูกแชร์ออกไปเปิดได้ตลอด
