# แผนลงมือรอบ 2 — หน้าป่าไม้สาธารณะ

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** เปิด `/forest` ให้คนทั่วไปดูชั้นข้อมูลป่าไม้ทั้งเจ็ดได้โดยไม่ต้องล็อกอิน และให้

**Architecture:** ไม่มีของใหม่ระดับโครงสร้าง — `MapViewer`, `/api/forest/layers` และ
`/api/forest/layers/[id]/geojson` มีครบตั้งแต่รอบ 1B แล้ว รอบนี้คือหน้าเว็บหนึ่งหน้า

**Tech Stack:** TypeScript · Next.js Pages Router · SWR · Leaflet · Vitest

## Task 2: จานสีแยกกลุ่มที่ตรวจด้วยเครื่องแล้ว

**Files:** Modify `src/lib/map-style.ts` · Create `src/lib/map-style.test.ts`

- [ ] **Step 1: รู้ก่อนว่าของเดิมพัง**

`GROUP_PALETTE` ชุดเดิม 12 สีถูกเลือกด้วยตา รันตัวตรวจแล้วได้:

```
[FAIL] Normal-vision floor  #fbbf24↔#facc15 ΔE 3.4 — เหลืองสองตัวที่คนสายตาปกติก็แยกไม่ออก
[FAIL] CVD separation       #e879f9↔#38bdf8 ΔE 0.3 (deutan) — คนตาบอดสีเขียว-แดงเห็นเป็นสีเดียวกัน
```

นี่เป็นข้อบกพร่องที่มีอยู่แล้วบน `/map` (โซนแปลงที่ดิน 16 กลุ่ม · หมู่บ้าน 11 กลุ่ม)
ไม่ใช่เรื่องที่ป่าไม้ทำให้เกิด แต่ต้องแก้ในรอบนี้เพราะแหล่งน้ำกับป่าสงวนจะมาใช้ตารางเดียวกัน

- [ ] **Step 2: แทนที่ด้วยชุดที่ค้นแบบ greedy แล้ว**

```ts
export const GROUP_PALETTE = [
  '#E69F00', '#56B4E9', '#009E73', '#0072B2', '#D55E00', '#AA3377', '#8b5cf6',
  '#ec4899', '#d946ef', '#117733', '#999933', '#b91c1c',
];
```

**เจ็ดสีแรกคือส่วนที่รับประกันได้** — ผ่านทุกด่านทั้งบนพื้นสว่างและพื้นเข้ม:

```
[PASS] CVD separation      คู่แย่สุด #AA3377↔#009E73 ΔE 10.3 (deutan)
[PASS] Normal-vision floor คู่แย่สุด #D55E00↔#E69F00 ΔE 15.6
```

**ช่องที่ 8–12 รับประกันไม่ได้** และนั่นไม่ใช่ความขี้เกียจ — ค้นทั่วพูล Tailwind 500/600/700
ทุกเฉดบวก Okabe-Ito และ Tol แล้ว การเพิ่มสีที่แปดที่ยังคง ΔE ≥ 15 ไว้ทุกคู่โดยอยู่ในแถบ
ความสว่างที่อ่านออกทั้งบนภาพดาวเทียมและแผนที่ถนน **ไม่มี** ดีที่สุดที่หาได้คือ 14.5

เก็บสิบสองช่องไว้เท่าเดิมเพื่อไม่ให้ `/map` ถอยหลัง (โซน 16 กลุ่มจะเริ่มวนสีเร็วขึ้นถ้าตัดเหลือเจ็ด)
และเพราะ `buildColorGroups` ไล่สีตามลำดับ ชั้นที่มี ≤ 7 กลุ่ม — ซึ่งคือป่าไม้ทั้งสองชั้น —
จะแตะเฉพาะหัวที่ตรวจแล้วเสมอ

คำสั่งที่ใช้ตรวจ (เขียนไว้ในคอมเมนต์ด้วย เพื่อให้คนถัดไปรันซ้ำได้):

```bash
node scripts/validate_palette.js "#E69F00,#56B4E9,#009E73,#0072B2,#D55E00,#AA3377,#8b5cf6" \
  --mode light --pairs all
```

`--pairs all` ไม่ใช่ `--pairs adjacent` เพราะบนแผนที่ กลุ่มไหนก็ติดกับกลุ่มไหนก็ได้

- [ ] **Step 3: `COLOR_BY` สองรายการ**

```ts
'forest-stream': 'class_th',
'forest-reserve': 'province',
```

เขียนคอมเมนต์กำกับว่าทั้งสองอยู่ในเพดานเจ็ดกลุ่ม (6 และ 3) พร้อมวันที่นับ — เพื่อให้คนที่
เพิ่มชั้นถัดไปรู้ว่าเพดานมีอยู่จริง

- [ ] **Step 4: เทสต์ตรึงจานสี**

`src/lib/map-style.test.ts` ใหม่ — ตรึงว่า

1. เจ็ดสีแรกเป็นค่าที่ตรวจแล้วเป๊ะ ๆ (เทสต์แตกทันทีถ้ามีคน "จัดสีให้สวยขึ้น")
2. ไม่มีสีซ้ำในตาราง
3. ทุกชั้นใน `COLOR_BY` มีสไตล์ของตัวเองใน `LAYER_STYLES`
4. `buildColorGroups` ให้สีต่างกันครบเมื่อค่าไม่เกินขนาดจาน และวนซ้ำเมื่อเกิน

## Task 3: ป้ายสวิตช์แยกสีที่ไม่ผูกกับโดเมนแผนที่

`MapViewer` ใช้ร่วมกันสี่หน้า (`/map`, `/forest`, `/admin/map/viewer`, `/admin/forest/viewer`)

## ที่จงใจไม่ทำในรอบนี้

**`defaultOn` บนเอกสารชั้นข้อมูล** — สเปกจัดไว้ในรอบ 2 แต่ตอนนี้ `LAYER_STYLES` เก็บค่า
`defaultOn` ของทั้งเจ็ดชั้นอยู่แล้วและ `MapViewer` อ่านจากตรงนั้น ผลลัพธ์ที่ผู้ใช้เห็นจึง
ถูกต้องครบแล้ว การเดินสายจากฐานข้อมูล → API สาธารณะ → `ViewerLayer` ตอนนี้จะได้ท่อที่
ไม่มีอะไรไหลผ่าน เพราะยังไม่มีหน้าไหนตั้งค่านี้ได้

ย้ายไปรอบ 3 ซึ่งเป็นรอบที่เจ้าหน้าที่สร้างชั้นเองได้ — ชั้นที่สร้างใหม่ไม่มีรายการใน
`LAYER_STYLES` จึงต้องมีทางบอกค่านี้จากหลังบ้านจริง ๆ และจะมีหน้าตั้งค่าให้กรอกพร้อมกัน

**ต้องแก้คอมเมนต์ใน `src/types/forest.ts`** ที่เขียนว่า "เมื่อรอบ 1B/2 มาถึง" ให้ตรงกับ
ความจริง ไม่งั้นคนอ่านจะไปหาโค้ดที่ไม่มีอยู่
